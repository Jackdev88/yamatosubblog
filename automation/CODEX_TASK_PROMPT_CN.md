# 大和字幕云端博客长期执行规则

## 运行目标与配置
仓库：Jackdev88/yamatosubblog。网站：https://www.yamatosub.com/。
目标执行时间：每天北京时间 10:00，IANA 时区 Asia/Shanghai。此文件记录目标配置，不证明定时任务已保存或启用。只更新已经确认属于本博客的云端任务，不创建重复任务，不改用其他任务。
每次运行都从仓库 main 读取本文件、automation/EDITORIAL_PLAN_CN.md、automation/README.md、automation/seo-topics.json 和当前博客导入工作流；不依赖聊天记忆、电脑文件、临时附件，也不调用 OpenAI API。规划缺失或配置 PR 尚未合并时，报告阻塞，不沿用旧提示生成文章。用户最新明确指令优先，产品当前事实须重新核验。

## 每次执行
1. 读取 main 的文章投递目录、历史文章、开放 PR 和官网博客。按标题、slug、主题及主要搜索意图去重，不只比较字符串。已使用主题和旧稿件不覆盖。
2. 用 Asia/Shanghai 判断当天日期。检查文件日期、选题 usedAt、PR 创建时间和内容；当天已生成、提交、合并或导入过文章，就处理那份稿件的状态，不生成第二篇。关闭的 PR 也检查，避免重复触发新稿。开始写前、创建 PR 前及启用自动合并前重新核对当天和开放 PR；使用稳定的 automation/blog-YYYY-MM-DD 分支复用已有工作，同日多份候选须暂停并报告，不自动选择并合并。
3. 从未使用且核验条件可满足的主题中选一个，不机械选第一条。优先交替观看、字幕寻找、质量、费用/流程、学习、创作场景，参考最近至少七篇，不连续写同一类工具教程。待写不足七篇时，结合规划与新研究补充去重后的题目到同一选题表；保留所有旧条目、状态、usedAt 和未知字段。editorialStatus 为 duplicate/deferred 的题不得直接发布；将其作为历史候选保留。
4. 先研究再写。优先官方文档与一手资料，核对平台/版本/设备范围；用户反馈仅作需求线索。没有实测就不宣称实测；凡操作确实需要实测而无法执行，改写可核验问题或换题，不编菜单、故障、性能、搜索量。平台无法访问时不能凭第三方镜像猜入口。
5. 中文，称呼读者“你”，开头直接进入具体处境，一篇解决一个需求。普通稿约 1200–1800 个汉字，复杂稿约 1800–2500 个汉字；同时满足实际导入接口清洗后长度与各字段限制。必须从可靠产品资料/后台获知导入限制并记录证据；仓库 README 没给数值时不能把编辑字数当接口阈值，无法确认则不启用自动合并，保留 PR 报告。
6. 不强制 FAQ、总结、固定数量小标题、工具榜单或推广。禁空泛开场、夸大宣传、“值得注意的是”“不仅……更……”等套话；不得虚构经历、用户故事、截图、实测、准确率。示例标为自写示例。取消固定核验尾注和结尾集中堆链接，价格、数据及关键外部论断在相关段落给必要来源；研究来源、版本、核验日期和未解决疑问写入 PR 说明。
7. 大和字幕围绕生成、翻译、处理、编辑、管理和资源协作发展。字幕翻译、音视频转字幕、项目/任务管理、整体时间轴调整、SRT/VTT 转换和双语合并涉及具体功能、费用、限制时，核验当前官网或可靠产品资料。在线编辑器、AI 校对、术语库、论坛、资源社区、实时插件只是规划方向；只可写需求与通用方法，不能写成已上线操作。实时翻译区分已有字幕翻译与音频识别后翻译，不承诺全站可用、零延迟、任意链接导入。
8. 自然结合迅雷、PotPlayer、VLC、SubHD、assrt、字幕库、云盘、YouTube 等真实问题，能在原平台解决就直接说明。大和内链仅在相关时出现。不提供盗版地址、保护绕过和未经授权转载指引；行业增长/衰退等结论必须有证据。
9. 按 automation/README.md 的现有十个 JSON 字段保存为 automation/blog-inbox/YYYY-MM-DD-<slug>.json，source 保持 codex-scheduled-task。slug 为小写英文与连字符；正文仅用 p/h2/h3/ul/ol/li/strong/a 等已确认安全标签，无 script/style/iframe、事件属性或危险 URL。检查 JSON、字段类型、实际导入长度、HTML、内外链接及重复标题/slug/搜索意图。读取现行接口要求，必要时取交集；无法确认的链接改为普通文字或换来源。
10. 从最新 main 创建独立文章分支，一起提交新增文章及主题 status=used、usedAt=北京时间日期。usedAt 表示本次稿件已产出，不代表公开发布。日常文章 PR 只能改一个新增文章 JSON 和 automation/seo-topics.json；不得改旧稿、代码、依赖、工作流、数据库、凭据或安全配置。记录文件、目标用户、研究与自检证据、字数及接口长度规则。配置 PR 必须独立，不自动合并。
11. 只对本任务能确认创建的文章 PR 启用 GitHub 自动合并；先确认完整 diff 范围、内容自检、最新 head SHA 的必要 PR 检查通过、无冲突、仓库允许自动合并且保护规则要求这些检查。零检查不能当作通过；只有合并后的导入工作流也不算 PR 检查。若立即可合并而工具不能启用自动合并，保留 PR 报告，不偷偷改用直接 merge。权限不足、失败、冲突、保护不可确认或要求审核时保留 PR；不绕过限制，不直接推 main，不修改安全设置/凭据/发布工作流。
12. 合并后核对对应合并 SHA 的现有博客导入工作流，读取导入响应并区分业务 ok、draft/published 与仅 CI 成功。失败重试前先检查同 slug/标题是否已导入、先前响应/后台状态；不能确认时暂停重试。多文件流程可能部分成功，不盲目重跑整个流程。成功导入不再重投。
13. 保持网站现有导入模式，不将草稿改公开。报告独立状态：PR 链接与合并状态、导入工作流结果、网站草稿/公开/无法确认。未来运行继续核对未完成 PR 和导入，不为了报告完成而编成功。
